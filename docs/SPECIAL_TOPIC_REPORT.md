## 摘要

本研究建置一套以邊緣人工智慧（Edge AI）為核心的**飛機機翼表面損傷即時檢測系統**。系統以 NVIDIA Jetson Orin Nano 作為邊緣運算主機，結合 YOLO11s 深度學習物件偵測模型，可同時辨識七種損傷類別（裂縫、凹痕、掉鉚釘、蒙皮、機身損傷、機翼損傷、引擎損傷）；再透過 WebRTC 即時串流，將手機相機畫面傳給主機進行推理，並把偵測方框即時疊回手機畫面，實現「手機一照、立刻告警」的場域檢測體驗。研究中詳細處理了三個實務關鍵：**無線熱點穩定度**（rtl8822ce 驅動休眠導致的連線不穩）、**手機直拿畫面的疊框對齊**（object-fit:cover 幾何校正與方向修正）、以及**資料集類別不平衡**（以水平翻轉增強小類樣本）。最後並設計「自動訓練 → 自動部署」的流水線，訓練完成後不需人工介入即可讓主機使用新模型。實驗結果顯示系統可在手機端即時、穩定地顯示七類損傷偵測框，並針對少數類損傷持續改善辨識能力。

**關鍵字**：YOLO11、物件偵測、Jetson、邊緣運算、WebRTC、即時影像串流、機翼損傷檢測

## 第一章 緒論

### 1.1 研究動機

飛機外表面的微小損傷（裂縫、凹痕、鉚釘鬆脫、蒙皮破損等）可能影響飛行安全，需要定期、全面地檢查。傳統人工目視檢查耗時且易漏，而大型瑕疵檢測設備成本高昂、不易攜帶到機坪現場。本組成員來自飛修與電子領域，希望把 AI 影像辨識帶到「現場直接拿手機照」的場景，做出一套低成本、可攜、即時的損傷檢測工具。

### 1.2 研究目的

1. 建立一套可在**現地（無網際網路）**運作的損傷偵測系統。
2. 讓**一般使用者（不需程式背景）**拿起手機即可完成檢測。
3. 系統需能即時回饋（框出損傷位置）與精準確認（七類分類）。
4. 建立可持續改進的流程：**多拍照片 → 自動再訓練 → 自動部署**。

### 1.3 研究範圍

- 損傷類型：限定七類（見第三章 3.2）。
- 硬體平台：Jetson Orin Nano 主機 + 智慧型手機相機。
- 演算法：以 YOLO11s 單階段物件偵測為主。
- 場域：手機透過主機自建之 WiFi 熱點連線，於機坪現場使用。

## 第二章 文獻探討

### 2.1 深度學習物件偵測

物件偵測分兩大流派：

- **二階段（Two-stage）**：如 R-CNN 系列，先找出候選區域再分類，準確但慢。
- **單階段（One-stage）**：如 YOLO 系列，直接在整張圖上一次輸出「位置框 + 類別 + 信心度」，速度快、適合即時應用。

本專題採用 **YOLO11s**（Ultralytics 維護的 YOLO 最新一代），其體積小、精度與速度均衡，非常適合 Jetson 這類低功耗邊緣裝置。

### 2.2 邊緣運算（Edge AI）

把 AI 推理放到裝置本端（edge）而非雲端，優點是：不需網路、延遲低、資料不出本機。Jetson Orin Nano 內建 GPU 加速單元，可在 7.6GB 記憶體內運行中等規模的 YOLO 模型，兼顧功耗（適合現場攜帶）與即時性。

### 2.3 WebRTC 即時串流

WebRTC 是瀏覽器內建的即時影音傳輸標準，能雙向傳送畫素等級的串流。本專題用它來：

- **上行**：手機相機 → Jetson 推理（維持手機原生解析度，避免經壓縮傳輸掉細節）。
- **下行**：Jetson 畫好框的畫面 → 手機顯示。

相比傳統「每隔 250ms 送一張 JPEG」的方式，WebRTC 提供更流暢、更高解析度的即時體驗。

## 第三章 系統設計與架構

### 3.1 整體架構

```
┌──────────────┐  上行(手機原始相機畫面)   ┌────────────────────┐
│  手機瀏覽器   │ ────────────────────────▶ │   Jetson Orin Nano   │
│  (相機/顯示)  │ ◀──────────────────────── │  YOLO11s 七類推理     │
└──────────────┘  下行(已畫框的翻譯畫面)     │  WebRTC 串流/API     │
        │                                   └────────────────────┘
        │  WiFi 熱點「AirCraft67Team」(10.42.0.1)
        └────────────────────────────────────────
```

- **前端**（手機端網頁）：取得相機權限、顯示即時串流與偵測方框、提供「即時診斷」與「定格診斷」兩種模式。
- **後端**（Jetson 端）：接收串流 → 運行深度學習推理 → 將歸一化框回傳前端疊加，同時把標註後的畫面推回顯示。

### 3.2 損傷類別定義（七類）

| ID | 類別名稱（英文） | 中文 | 說明 |
|---|---|---|---|
| 0 | Crack | 裂縫 | 表面裂紋 |
| 1 | Dent | 凹痕 | 撞擊凹陷 |
| 2 | Missing_Fastener | 掉鉚釘 | 鉚釘缺失 |
| 3 | Skin_Cover | 蒙皮 | 蒙皮破損/掀起 |
| 4 | Fuselage_damage | 機身損傷 | 機身結構傷害 |
| 5 | Wing_damage | 機翼損傷 | 機翼結構傷害 |
| 6 | Engine_damage | 引擎損傷 | 引擎進氣/涵道等損傷 |

### 3.3 兩種診斷模式

| 模式 | 作法 | 用途 |
|---|---|---|
| **即時診斷（Live）** | 每幀跑 1 次推理，即時疊框 | 掃描、快速巡查 |
| **定格診斷（定格）** | 凍結目前畫面，同一幀跑 3 次推理並合併，取最高信心 | 驗證可疑處、給最終答案 |

兩種模式皆使用同一個七類 YOLO11s 模型，確保結果一致。

## 第五章 軟體實作

### 5.1 技術棧

- 後端：Python + FastAPI + Uvicorn（HTTPS 服務 `:8000`）
- 推理：Ultralytics YOLO11s + OpenCV
- 串流：WebRTC（aiortc）
- 前端：原生 HTML/JavaScript/CSS（行動裝置最佳化）
- 模型檔案：`webUI_workspace/models/yolo11s.pt`

### 5.2 主要 API

| 方法 | 路徑 | 功能 | 模型 |
|---|---|---|---|
| GET | `/` | 回傳操作網頁 | — |
| GET | `/status` | 主機狀態檢查 | — |
| GET | `/webrtc/offer`、`POST /webrtc/answer` | 建立 WebRTC 串流 | — |
| POST | `/infer_hd` | 定格診斷（3 次合併） | YOLO11s |
| POST | `/diagnose_upload` | 上傳照片診斷 | YOLO11s |

### 5.3 「手機直拿」的疊框對齊（重要實作）

手機**直拿**拍攝時影像是直式（portrait），而網頁播放區用 `aspect-ratio: 4/3 + object-fit:cover` 呈現。若不處理，AI 回傳的歸一化框會與實際畫面錯位。本專題實作 `_coverRect()` 計算 cover 裁切後的實際可視區域，將框轉換到相同座標系統；並修正上游幀的方向，確保「AI 看到的」與「手機顯示的」方向一致。此修正讓即時框與定格框位置都正確。

### 5.4 「連上熱點卻沒網路」的修復

實測發現 rtl8822ce 驅動在省電模式下會讓手機拿到 IP 卻無法通訊。解法：以 `rmmod + modprobe` 重新載入模組，傳遞關閉省電的參數，並持久化為模組設定檔，重開機仍有效。

### 5.5 防止快取造成「舊程式」

現場評審的手機可能載入舊版網頁 JS。系統已對整個網站加上 `Cache-Control: no-store`，且網頁會依 JS 檔修改時間自動換版本號，確保任何手機第一次連上都拿到最新版程式。

## 第六章 資料集與模型訓練

### 6.1 資料來源

訓練資料來自多個公開 Roboflow 航空損傷資料集之整合，經整理、統一類別、轉成 YOLO 標註格式，匯集成 **7 類資料集**（`yolo_workspace_v4`）。

### 6.2 資料量與類別不平衡問題

初步統計（原始資料，train 共 11,315 張圖）：

| 類別 | 含該類的圖片數 |
|---|---|
| Crack（裂縫） | 5,585 |
| Dent（凹痕） | 4,363 |
| Missing_Fastener（掉鉚釘） | 2,683 |
| Fuselage_damage（機身損傷） | 1,298 |
| Wing_damage（機翼損傷） | 1,024 |
| Skin_Cover（蒙皮） | 952 |
| Engine_damage（引擎損傷） | 918 |

> **問題**：`Skin_Cover / Wing_damage / Engine_damage` 這幾類的樣本數只有裂縫的六分之一左右。深度學習模型在類別不平衡時，會偏向學習樣本多的類別，導致**少數類損傷「看不出來」**——這正是早期實測「兩個模式的某些損傷都偵測不到」的主因之一。

### 6.3 資料平衡方法

本研究以**水平翻轉（horizontal flip）**對少數類做數據增強，把四類少數類（Skin_Cover / Fuselage_damage / Wing_damage / Engine_damage）皆補到 2,500 張圖片；

- 翻轉需同步替換標註框的 X 座標（`1 - x`），本研究一併處理。
- 平衡後：train 共 **17,123 張**，每類均 ≥ 2,500 張。
- 大類（Crack/Dent/掉鉚釘）維持原數量不砍，避免損失既有學習成果。

### 6.4 訓練設定

| 參數 | 值 | 說明 |
|---|---|---|
| 模型架構 | YOLO11s | 精度/速度均衡 |
| 續練來源 | 前一版 best.pt | 保留既有特徵 |
| 影像尺寸 imgsz | 512（加快後版本） | 512 像素餵入 |
| Batch size | 16（加快後版本） | 記憶體 4GB 可負擔 |
| Epochs | 120（含早停 patience=30） | 指標停滯即自動停止 |
| 優化器 | MuSGD | 自動挑選 |
| 硬體 | GTX 1050 Ti | 工作站端 |

### 6.5 自動訓練 → 自動部署流水線

為避免人力空等，本研究建立自動化流程：

1. 工作站啟動背景訓練（`nohup`，斷線不受影響）。
2. Jetson 端每隔 5 分鐘以 cron 執行監看腳本（`deploy_watcher.py`）。
3. 偵測到訓練結束後，自動下載 `best.pt` → 覆蓋主機模型 → 重啟服務。
4. 全程無需人工介入，且以 lock 檔保證只部署一次。

- **即時診斷**：手機直拿即時照到損傷，可看到對應綠色框與類別標籤，疊框位置正確不偏移。

## 第八章 結論與未來展望

### 8.1 結論

1. 本研究成功建置「手機 + Jetson + YOLO11s」的現地可攜損傷檢測系統，兩種診斷模式皆可正常運作。
2. 解決了無線熱點連線不穩、手機直拿疊框錯位、網頁快取舊程式三個實務關鍵問題。
3. 導入資料平衡與自動訓練部署流水線，使系統可持續透過新增照片自我改進。

### 8.2 未來展望

1. **蒐集實機照片**：與飛修組員合作，多拍 Skin_Cover / Wing_damage / Engine_damage 的真實照片，從根本解決少數類樣本不足。
2. **輕量化即時模型**：另行訓練真正的 YOLO11n（更小）模型做即時串流，讓 FPS 更高。
3. **多機協作**：一台主機同時服務多支手機、多角度同時檢測。
4. **損傷嚴重度 LLM 報告**：結合本地大語言模型，對重大損傷自動產生處置建議。
5. **量化部署**：將模型轉為 TensorRT INT8 引擎，進一步省電提速。
