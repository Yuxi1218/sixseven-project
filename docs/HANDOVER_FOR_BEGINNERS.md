# Sixseven 機翼損傷檢測系統 — 交接手冊（給沒寫過程式的人）

> 這份手冊假設你**完全沒寫過程式**。只要照著做就能把系統開起來、讓手機連上去、看到偵測結果。
> 遇到不懂的地方，先看「第 8 節 常見問題」，再不行就找寫程式的人。

---

## 1. 這套系統到底在做什麼？

我們做了一個「眼睛」+「大腦」組合，用來檢查飛機表面有沒有損傷：

```
手機相機（眼睛）  ──WiFi──>   Jetson 主機（大腦）  ──>  在手機上畫框框給你看
有損傷就框出來      認出「這是裂縫/凹痕/掉鉚釘…」
```

- **手機**：負責當鏡頭，把畫面即時傳給主機。（也可以上傳照片）
- **Jetson 主機**（一台手掌大的小電腦）：真正的 AI 判斷都發生在這裡。它認出哪裡有損傷、是 7 種類型的哪一種，然後在手機畫面上把損傷位置用綠色框標出來。
- 不用手動操作：手機連上主機的 WiFi，打開瀏覽器，畫面就自己開始偵測了。

### 三個模式（手機網頁上的按鈕）

| 按鈕 | 名稱 | 做什麼 | 何時用 |
|---|---|---|---|
| 進入網頁就自動開始 | **即時診斷（Live）** | 鏡頭對著哪裡，框框就即時跟著移動 | 平時掃描、比對用 |
| **開始診斷** | **定格診斷** | 凍結目前畫面，主機用最高品質再確認一次，跑 3 次取最穩結果 | 有可疑處、要給「最終答案」時 |
| **繼續拍攝** | 回到即時模式 | 診斷完回到即時掃描 | 每次定格後 |

## 2. 現場開機 SOP（照著做就對了）

一次完整流程，約 3 分鐘：

```
步驟 1   開 Jetson（插電 → 按電源）。等 1~2 分鐘它自己開完。
步驟 2   確認 WiFi 熱點「AirCraft67Team」出現了。
         （手機的 WiFi 清單看得到 = 熱點正常）
步驟 3   手機連上「AirCraft67Team」。密碼記在現場（預設接頭見第 6 節）。
步驟 4   手機打開瀏覽器（Chrome 或 Safari 都可以）。
步驟 5   網址打：https://10.42.0.1:8000
步驟 6   瀏覽器會警告「不安全」（因為憑證是自己做的，正常），點「進階 → 繼續前往」。
步驟 7   允許網站使用相機。看到畫面 + 綠色框 = 完成！
```

> **重點**：只能用 **https**（多一個 s），不能用 http，不然手機相機打不開。

### 手機畫面說明

- 左上角綠點 = 連線正常；紅燈 = 有問題（往第 7 節查）。
- FPS：畫面每秒更新幾次。有框框有畫面代表正常，數字大小不重要。
- 偵測數：目前畫面上框出幾個損傷。
- 綠色框 + 文字 = AI 認為這裡有損傷，文字是類型（例：Crack = 裂縫）跟信心百分比。

## 3. 現場若突然不能用（3 分鐘快速排除）

依序做，做完一項就回頭試：

1. **手機重新整理網頁**（下拉更新 / 右上角重新整理）。快取已設定不會留舊版，但重開網頁最保險。
2. **手機重連 WiFi**：關 WiFi → 開 WiFi → 再點 AirCraft67Team。
3. **檢查熱點在不在**：手機 WiFi 清單沒有 AirCraft67Team → 代表主機端熱點掛了。有人 SSH 到主機執行 `bash /tmp/opencode/start_webrtc.sh`（重開網頁服務，不影響熱點）；若熱點本身沒了，見第 7 節的「熱點救援」。
4. **重開整個主機**：最後手段，電源拔掉重插。開完再走一次第 2 節流程。

> 只要手機 WiFi 看得到 AirCraft67Team，通常重開網頁服務就回來了。

## 4. Jetson / 主機基本認識（非必讀，但會更安心）

### 它是台電腦

Jetson 就是一台 Linux 電腦，只是省電、隨身。我們透過 SSH（一種遠端控制方式）操作它。

**登入方式**：在你的電腦開終端機（Mac 的 Terminal / Windows 的 PowerShell），打：

```
ssh sixseven@<主機IP>
```

IP 若不知道，看第 5 節。密碼是現場共用的那個（寫在第 6 節）。

### 常用指令（不用背，照抄）

| 目的 | 指令 |
|---|---|
| 重開網頁服務（手機連不上時最常做） | `bash /tmp/opencode/start_webrtc.sh` |
| 看服務有沒有在跑 | `ps aux \| grep main.py \| grep -v grep` |
| 看即時 log（有東西在跑就代表正常，會一直跳） | `tail -f /tmp/opencode/https_webrtc27.log` |
| 從 log 跳出來 | 按 `Ctrl + C` |
| 看目前 IP | `hostname -I` |

> 用 SSH 操作時**不要關掉視窗讓它繼續跑**；`start_webrtc.sh` 已設計成背景執行，關掉 SSH 也沒關係。

## 5. 程式怎麼運作（用「餐廳」比喻）

不用懂程式也能有個概念，這樣除錯時不會慌。

| 元件 | 我們的比喻 | 真實檔案 |
|---|---|---|
| **網頁（前端）** | 餐廳的服務生：收客人點單、把菜端上桌 | `webUI_workspace/static/app.js`、`webUI_workspace/templates/index.html` |
| **主程式（後端）** | 廚房總管：決定先做哪道、出菜 | `webUI_workspace/main.py` |
| **串流處理** | 外送員：把手機畫面接力送到廚房、再把框過的畫面送回來 | `webUI_workspace/webrtc_stream.py` |
| **AI 模型** | 廚師：認出這是裂縫還是凹痕 | `webUI_workspace/models/yolo11s.pt` |
| **資料集** | 食譜：廚師是「看過幾萬張損傷照片」學來的 | `yolo_workspace_v4`（在訓練的筆電上也有） |

**簡單流程**：

```
手機拍畫面 → 送到 Jetson → AI 認損傷 → 算出框框位置 → 傳回手機 → 手機把框畫在畫面上
```

每一秒鐘這流程重複好幾次，看起來就像「即時」。

### 「訓練模型」是什麼意思？

AI 不是發明的，是「餵照片學」的：我們給它幾萬張「右邊這種圖 = 裂縫」「左邊這種 = 凹痕」的標註照片，它自己找規律。餵得越多、越平均，它越會認。

**為什麼目前有些損傷認不出來**：我們 7 種類型裡，`Skin_Cover`（蒙皮）/`Wing_damage`（機翼損傷）/`Engine_damage`（引擎損傷）的照片特別少（幾百張 vs 裂縫幾千張），所以它學不夠。**多拍這些類型的照片 = 直接讓系統變強**，這是目前最有用的改進。

### 現場熱點

- SSID：`AirCraft67Team`，主機 IP：`10.42.0.1`，手機網頁：`https://10.42.0.1:8000`
- 手機拿到類似 `10.42.0.69` 的 IP 都算正常（DHCP 分配）。

### 熱點為什麼特別可靠（技術小事）

主機的 WiFi 晶片型號是 rtl8822ce，我們把它的省電／休眠功能關掉了，還固定在 2.4GHz 第 1 頻道，所以手機比較不容易「連上卻沒網路」。設定存在 `/etc/modprobe.d/rtl8822ce-ap.conf`，**不要亂改**。

## 7. 各種狀況的處理

| 狀況 | 原因（白話） | 解法 |
|---|---|---|
| 手機連不上熱點 | 主機 WiFi 休眠了 | 重開主機 → 手機重連（第 3 節） |
| 連上熱點但網頁開不了 | 網頁服務掛了 | SSH 跑 `bash /tmp/opencode/start_webrtc.sh` |
| 網頁出現但沒畫面 | 應該開 https，開成 http | 網址確認 `https://10.42.0.1:8000` |
| 沒彈相機詢問視窗 | 同上 / 瀏覽器沒允許相機 | 換 Chrome 或 Safari 再試 |
| 鏡頭有畫面但沒有框 | 那塊沒有被模型認出的損傷，正常；或模型偏弱 | 先按「開始診斷」定格確認 |
| 定格也不認 | 那類型照片太少，模型沒學會 | 拍這種照片補資料（見第 8 節） |
| 主機完全沒反應 | 硬體 | 拔電重開，再走第 2 節 |

**「熱點救援」**（現場熱點消失時，比較進階，給做得到的人）：
```bash
# 在主機上重建熱點（管理者權限）
sudo nmcli connection delete AirCraft67Team 2>/dev/null
sudo nmcli connection add type wifi ifname wlan0 con-name AirCraft67Team \
  ssid AirCraft67Team mode ap \
  802-11-wireless.band bg 802-11-wireless.channel 1 \
  802-11-wireless.powersave 2 \
  wifi-sec.key-mgmt wpa-psk wifi-sec.psk <熱點密碼> \
  ipv4.method shared ipv4.addresses 10.42.0.1/24
sudo nmcli connection up AirCraft67Team
```
做完後重開網頁服務，手機重新連一次。

## 8. 讓模型變強（給想「加照片」的人）

1. **用同一台手機**，在現場開即時診斷，把畫面對準損傷處，按「開始診斷」保存的那張照片就可以用。
2. 蒐集重點：**多拍目前最少的那幾類**——`Skin_Cover`（蒙皮）、`Wing_damage`（機翼）、`Engine_damage`（引擎）、`Fuselage_damage`（機身）。
3. 拍越多越好（每類至少幾十張、上百張更好），交給會寫程式的人標記（用免費的 labelImg / CVAT 畫框）。
4. 標好後放到訓練資料夾 → 重新訓練 → 換新權重 → 完成。

> 照片品質 > 數量：損傷要清楚、背景乾淨、盡量一張一種損傷，AI 才學得懂。
